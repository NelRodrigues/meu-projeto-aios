# Story 1.1: Setup do projecto e deploy base

## Status
Approved

## Story
**Como** equipa Marca Digital,
**quero** o repositório `SIC-Global-Minds` criado a partir da base ISILDA, com projecto Supabase dedicado da GM e deploy na Vercel,
**para** ter uma fundação segura e limpa onde construir todos os épicos seguintes.

## Acceptance Criteria
1. Projecto Supabase **dedicado** criado (plano Pro — pg_cron, backups, sem pausa por inactividade) com extensões activas: `pg_cron`, `pg_net`, `pgcrypto`, `pgvector` (migração 001).
2. Repositório `SIC-Global-Minds` derivado da base ISILDA compila (`npm run build`) com Next.js 16 + React 19 + Tailwind v4 + `@supabase/ssr`.
3. Migração 002 aplicada: clone das tabelas base **com rename `clientes`→`leads` e `cliente_id`→`lead_id` em cascata** (tabelas: `profiles`, `leads`, `interacoes`, `mudancas_estagio`, `mensagens_whatsapp`, `integration_keys`); `whatsapp_instances` sem coluna `tenant_id`. Rollback SQL incluído.
4. Nenhuma referência "Isilda/Delicias" restante no código, configs, seeds ou package name (`grep -ri "isilda\|delicias"` limpo, excepto docs históricas).
5. Página de health-check pública (`app/health`) responde 200 no deploy Vercel.
6. RLS activa em TODAS as tabelas criadas — nenhuma tabela sem policy (verificável por query ao `pg_policies`).
7. `.env.example` completo (Supabase URL/keys, uazapi, Anthropic, Resend placeholders); chaves operacionais geridas via tabela `integration_keys` com fallback env.
8. Migrações numeradas com comentário do porquê + ficheiro de rollback (convenção §9 da arquitectura).
