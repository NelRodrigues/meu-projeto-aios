# Story 5.4: Templates Meta pela UI

## Status
Approved

## Story
**Como** Ana,
**quero** criar templates Meta e acompanhar a aprovação directamente pela UI do CRM,
**para** preparar campanhas oficiais sem depender de ninguém técnico nem do Business Manager.

## Acceptance Criteria
1. Formulário de criação de template funcional (categoria Utility/Marketing, idioma, corpo com variáveis `{{1}}`/`{{2}}` e exemplos obrigatórios) com preview estilo WhatsApp; validação das regras da Meta antes da submissão; submissão via `create-whatsapp-template` cria a row em `whatsapp_cloud_templates` com `status='PENDING'` e `meta_template_id` preenchido.
2. Sincronização de estado **PENDING → APPROVED/REJECTED** disponível de duas formas: botão manual na UI e cron via `sync-whatsapp-templates`; motivo de rejeição da Meta visível no detalhe do template.
3. Templates REJECTED editáveis e re-submissíveis (nova versão); só templates APPROVED aparecem no selector de campanhas Cloud API (integra com o AC3 da story 5.3).
4. **Primeiros templates reais da GM submetidos na Semana 2–3** (não deixar para o fim — a aprovação da Meta demora de minutos a 24h+): pelo menos 1 template de apresentação problema→solução para encarregados de educação e 1 para empresas, com copy validado pelo Rinaldo, com código de idioma Meta **`pt_PT`** e conteúdo em pt-AO pré-Acordo (e versão `en` se aplicável).

## Tasks / Subtasks
- [ ] Portar páginas de templates WhatsApp (`whatsapp-templates/`, `whatsapp-templates/novo`) para o App Router (AC: 1)
  - [ ] Formulário com categoria, idioma, corpo, variáveis + exemplos; preview estilo WhatsApp
  - [ ] Validação das regras Meta no cliente e na edge antes do POST a `{waba_id}/message_templates`
- [ ] Sincronização de estados (AC: 2)
  - [ ] Botão "Sincronizar" na lista → invoca `sync-whatsapp-templates` (UPSERT de estados)
  - [ ] Agendamento por cron da sincronização periódica; motivo de rejeição visível
- [ ] Ciclo de vida do template (AC: 3)
  - [ ] REJECTED → editar → re-submeter; selector de campanhas filtra `status='APPROVED'`
- [ ] Submeter os primeiros templates da GM (AC: 4) ⚠ **DEPENDÊNCIA EXTERNA:** WABA da GM configurada (setup guia 02) e copy aprovado pelo Rinaldo
  - [ ] Template encarregados (problema→solução) + template empresas; registar `meta_template_id` e acompanhar até APPROVED
- [ ] Verificação final: smoke Teste 5 do guia 04 (template `smoke_test_v1` → PENDING no banco → sync → APPROVED) (AC: 1, 2)

## Dev Notes
- **Fonte vinculativa:** [Arquitectura §4.3](../architecture/ARCHITECTURE-SIC-GLOBAL-MINDS.md) (`create-whatsapp-template`, `sync-whatsapp-templates`); §2.6 (M_mkt_008 cria `whatsapp_cloud_templates`); ADR-03 (campanhas frias só com templates oficiais).
- **Dependências:** story 5.1 (migração M_mkt_008 + edges deployadas); `whatsapp_instances` com provider Meta (`business_account_id`, `phone_number_id`). A story 5.3 consome os templates APPROVED daqui.
- **Setup Meta:** `marketing-module-package/05-setup-guide/02-whatsapp-cloud.md`; termos chave (WABA, PENDING/APPROVED/REJECTED) no `INSTRUCTIONS_FOR_CLAUDE.md`.
- **Timing crítico:** a aprovação Meta é assíncrona (minutos a 24h+) e pode rejeitar — por isso o AC4 obriga a submeter cedo (Semana 2–3), para haver template APPROVED disponível quando a 5.3 e o go-live precisarem.
- **Idioma dos templates (fixado — correcção C7/D9 da validação PO):** usar **`pt_PT`** como código de idioma Meta (a Meta não tem `pt_AO`; não usar o `pt_BR` do exemplo do guia); o **conteúdo** escreve-se em pt-AO pré-Acordo. Distinção código-de-idioma-Meta vs ortografia-do-conteúdo é intencional.

### Testing
- Criar template pela UI → `SELECT name, status, meta_template_id FROM whatsapp_cloud_templates` → `PENDING` + id preenchido.
- Sincronizar (botão e cron) → estado actualiza para APPROVED/REJECTED; motivo de rejeição visível quando REJECTED.
- Selector de campanhas Cloud API não lista templates PENDING/REJECTED.
- Templates reais da GM: 2+ submetidos com código de idioma `pt_PT`, estado acompanhado até APPROVED.
